# Systems as Attack Vectors

## Introduction

This room explores how threat actors target systems to gain unauthorized access, steal sensitive information, deploy malware, or disrupt business operations. It explains common attack vectors, including human-led attacks, software vulnerabilities, misconfigurations, and supply chain attacks.

The room also covers the role of Security Operations Center (SOC) analysts in identifying threats, investigating incidents, and recommending security improvements.

## Learning Objectives

* Understand the role of systems in the digital world
* Identify common attacks targeting systems
* Understand software vulnerabilities and misconfigurations
* Learn how supply chain attacks affect organizations
* Explore mitigation and detection techniques
* Practice identifying systems at risk and selecting remediation measures

## Tasks

### Task 1: Introduction

Introduced the role of SOC analysts in protecting systems against cyber threats and explained the importance of understanding how attackers target technical infrastructure.

### Task 2: Definition of System

Learned that systems include physical servers, workstations, and cloud platforms that store or process information.

A compromised system can have consequences beyond a single user account. For example, compromising a mail server may expose thousands of mailboxes, while breaching a critical industrial system can disrupt entire operations.

### Task 3: Attacks on Systems

Explored three common ways attackers compromise systems.

* Human-led attacks: Users may introduce threats by using weak or reused passwords, connecting malicious USB devices, or downloading malware.
* Vulnerabilities: Security flaws in software can allow attackers to exploit systems and gain unauthorized access.
* Supply chain attacks: Attackers compromise trusted software, applications, or libraries to distribute malicious code to their users.

### Task 4: Vulnerabilities

Learned about software vulnerabilities, zero-day vulnerabilities, CVE identifiers, and patches.

A zero-day vulnerability is a security flaw that is exploited before an effective fix is available or before defenders have had an opportunity to address it.

A patch is an update provided by a software vendor to fix a vulnerability. When a patch is unavailable, temporary mitigation measures may include restricting access, applying vendor-recommended workarounds, and monitoring for signs of exploitation.

### Task 5: Misconfigurations

Learned that misconfigurations are security weaknesses caused by incorrect or insecure system settings rather than software bugs.

Examples include weak passwords, publicly exposed databases, and excessive access permissions.

Common ways to identify and address misconfigurations include:

* Penetration testing to evaluate security under authorized attack simulations
* Vulnerability scanning to identify known weaknesses and insecure settings
* Configuration audits to compare systems against security best practices, such as CIS Benchmarks

Unlike software vulnerabilities, misconfigurations generally require correcting the affected settings rather than applying a software patch.

### Task 6: Practice

Practiced identifying systems at risk and selecting appropriate remediation measures in a simulated security dashboard.

The exercises reinforced the importance of evaluating system weaknesses and choosing suitable mitigations, such as patch management, antivirus protection, network restrictions, and IT security training.

### Task 7: Conclusion

Reviewed the importance of collaboration between SOC analysts and IT teams. SOC analysts can contribute to system security by sharing threat intelligence, identifying risks, investigating suspicious activity, and recommending improvements.

* How attackers target systems to gain access or disrupt operations

* How supply chain attacks can compromise trusted software
* The purpose of CVE identifiers and software patches
* How penetration testing, vulnerability scanning, and configuration audits help identify weaknesses

## Conclusion

This room demonstrated that protecting an organization requires securing both its people and its systems. Software vulnerabilities, insecure configurations, and compromised software dependencies can all create opportunities for attackers.

As a future SOC analyst, understanding these attack vectors helps me recognize potential risks, investigate security incidents, and recommend practical defensive measures. Continuous learning and collaboration with other teams are essential for improving an organization's security posture.
