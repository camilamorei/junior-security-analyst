# Introduction to SIEM

## Overview

This room introduces Security Information and Event Management (SIEM), a security solution used by Security Operations Center (SOC) analysts to collect, normalize, correlate, and analyze logs from multiple sources.

The room covers common log sources, SIEM capabilities, log ingestion methods, detection rules, and alert investigation through a simulated SIEM dashboard.

## Key Topics

### 1. Log Sources

Devices across a network continuously generate logs that record system and network activities. These logs help analysts investigate suspicious behavior, troubleshoot issues, and identify potential security incidents.

Log sources are divided into two main categories:

- Host-centric logs: generated by endpoints and systems, such as Windows and Linux machines.
- Network-centric logs: generated by network devices and services, such as firewalls, routers, and VPN connections.

Examples of host-centric activity include process execution, authentication attempts, and Windows Registry modifications. Network-centric activity includes web traffic, SSH connections, and VPN access.

### 2. Challenges of Log Management

Analyzing logs individually can be difficult because of several challenges:

- Numerous log sources generate large amounts of data.
- Logs are distributed across different devices.
- Individual logs may provide limited context.
- Manual analysis is time-consuming and may overlook important events.
- Different systems store logs in different formats.

A SIEM helps address these challenges by centralizing and correlating log data.

### 3. SIEM Capabilities

A SIEM platform provides several important security capabilities:

- Centralized log collection: gathers logs from multiple systems in one location.
- Log normalization: converts logs into a consistent structure.
- Log correlation: identifies relationships between events from different sources.
- Real-time alerting: triggers alerts when configured detection rules are matched.
- Dashboards and reporting: presents security events and useful metrics for analysts.

These capabilities improve visibility across an organization's environment and help SOC analysts investigate potential threats.

### 4. Log Sources and Ingestion

Different systems generate logs that can be forwarded to a SIEM for monitoring and analysis.

Examples include:

- Windows Event Logs, accessible through Event Viewer.
- Linux system and authentication logs.
- Web server logs, such as Apache access and error logs.
- Network device and security appliance logs.

Common log ingestion methods include:

- Agents or forwarders installed on endpoints.
- Syslog for centralized log transmission.
- Manual log uploads.
- Port forwarding to a SIEM listening service.

For Linux systems, HTTP-related logs may be stored in locations such as `/var/log/httpd`, depending on the system and web server configuration.

### 5. Detection Rules and Alert Analysis

SIEM detection rules use logical conditions to identify potentially suspicious activity.

Examples include:

- Multiple failed login attempts within a short period.
- A successful login following repeated failed attempts.
- Event log clearing activity.
- Execution of suspicious commands.
- Unusually large amounts of outbound network traffic.

Windows Event ID 104 can indicate an attempt to clear an event log. Windows Event ID 4688 can provide information about process creation.

When an alert is triggered, analysts examine the associated events and determine whether the activity is a true positive or a false positive.

A true positive represents a detection of actual suspicious or malicious activity. A false positive occurs when a rule flags activity that is not actually malicious.

### 6. Practical SIEM Investigation

The practical lab involved investigating an alert triggered by the execution of `cudominer.exe`.

The investigation required examining the related event, identifying the user and hostname, reviewing the detection rule, and determining whether the alert represented malicious activity.

The exercise demonstrated the importance of examining event details and correlating evidence before deciding how to handle an alert.

## Key Takeaways

- SIEM platforms centralize logs from multiple sources.
- Host-centric and network-centric logs provide different types of security context.
- Normalization makes logs easier to search and compare.
- Correlation helps analysts connect events that may appear harmless individually.
- Detection rules generate alerts when defined conditions are met.
- Alert investigation requires reviewing event details and validating the available evidence.
- True positives and false positives must be distinguished to support effective incident response.
